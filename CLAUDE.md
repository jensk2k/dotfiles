# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Scope:** these instructions are for working on the dotfiles. Because this file sits in `~`, Claude Code also loads it in every project below the home folder (e.g. `~/Projects/*`); there, ignore it and follow that project's own `CLAUDE.md`.

## What this is

`~/.dotfiles` is a **bare git repo** (remote `git@github.com:jensk2k/dotfiles.git`) whose work tree is `$HOME`. `~/.dotfiles` itself contains only git internals; the config files live at their real paths under `/home/jk`. Edit files in place (e.g. `~/.config/hypr/hyprland.lua`). This file (`~/CLAUDE.md`) is tracked in the repo too.

Machine: Arch Linux, Hyprland session launched through **uwsm**.

## Git commands

Always pass the git-dir and work-tree explicitly (the shell alias `dotfiles` does this, but aliases aren't available in non-interactive shells). Run from `$HOME`, not from inside `~/.dotfiles`, or git gets confused about the work tree:

```sh
cd ~ && git --git-dir=$HOME/.dotfiles --work-tree=$HOME status
git --git-dir=$HOME/.dotfiles ls-tree -r --name-only HEAD   # list tracked files
```

- `status.showUntrackedFiles = no`, and `core.excludesfile` (`~/.gitignore_global`) is `*` — everything is ignored by default. **New files must be added with `git add -f <path>`**. Modified tracked files can be added normally, but under an ignored directory like `.config` git still prints an "ignored by .gitignore" hint and exits non-zero even though the files were staged — don't chain `&& git commit` after it (or just use `-f`).
- In zsh, a `G="git --git-dir=..."` variable won't word-split; use a function (`G() { git --git-dir=$HOME/.dotfiles --work-tree=$HOME "$@"; }`).
- `lgdot` alias opens lazygit on this repo.
- Commit messages are short, lowercase, imperative ("update zsh config").

## Tracked configs and how they connect

- **Hyprland** (`~/.config/hypr/`) uses the **Lua config format** (`hyprland.lua`, `hl.*` API), not classic `hyprland.conf`. `hyprland.lua` only `require`s the modules in `modules/`, in order: `keybindings`, `autostart`, `monitors` (catch-all monitor + the generated files), `appearance` (general/decoration/animations/dwindle), `input` (keyboard, touchpad, gestures), `rules` (window and workspace rules). New settings go in the matching module. Dispatchers via `hyprctl dispatch` also take Lua expressions (`hl.dsp.window.close({...})`).
  - `monitors.{conf,lua}` and `workspaces.{conf,lua}` are generated by **nwg-displays** — don't hand-edit. `modules/monitors.lua` defines a catch-all `hl.monitor` and then `require`s the generated `monitors.lua`/`workspaces.lua` from the config root (the `.conf` versions are unused).
  - Autostarted apps are launched with `uwsm app -- <cmd>`; keep that wrapper for anything new. Session env vars (cursor, Qt platform theme) live in `~/.config/uwsm/env`, not in `hl.env` calls; changes need a re-login. Don't set `GTK_THEME` there: it would pin GTK apps to one theme, and `apply` switches light/dark (see Theme).
  - Companion daemons: hypridle (runs hyprlock), hyprpaper, hyprsunset.
  - Tried and set aside (Nov 2026): the **scrolling layout** (`hl.workspace_rule({ workspace = "8", layout = "scrolling" })` plus `colresize`/`consume`/`expel` keys); the user didn't see the point for now but may revisit it. Also **Waybar drawers** for things only reachable with the mouse (e.g. folding cpu/memory/temperature behind an icon): rejected, since Waybar can't open a drawer from a key. Drawers *are* used for volume and brightness (slider slides out on hover), because those levels are on keys anyway. Don't re-suggest either as new.
  - **Window swallowing** (`modules/rules.lua`): `misc.enable_swallow` with `swallow_regex = "^(kitty)$"`, so a GUI app started from a plain kitty window takes its place until it closes (popups, drop-down and cheat sheet have other classes and never swallow). Launching with `uwsm app --` or `setsid -f` avoids it, since only child processes of the terminal are swallowed.
  - **Drop-down terminal**: `SUPER + `` ` toggles `special:dropdown`; when that workspace is created empty, a `hl.on("workspace.created", …)` handler in `modules/rules.lua` starts `kitty --class dropdown -o background_opacity=1` (this replaces the `on_created_empty` workspace rule, deprecated in 0.57); the `dropdown-terminal` window rule floats it as a full-width panel under the bar (45% high). It keeps running while hidden. Special workspaces (it and the `SUPER + S` scratchpad) slide like a Quake console: `specialWorkspaceIn` = `slidevert top`, `specialWorkspaceOut` = `slidevert bottom` (the side is the entry edge; leaving goes to the opposite one, so Out needs `bottom` to go back up). Hyprland 0.57 accepts these sides for workspace slides although the wiki documents them only for windows.
  - Window rule `match` patterns must match the **whole** value (`^popup\\..*`, not `^popup\\.`); a prefix-only pattern silently never matches. Waybar's `window-rewrite` regexes are searches, so they don't need this. Desktop files' `StartupWMClass` can differ from the live class (Bitwarden is `bitwarden`); check with `hyprctl -j clients`.
  - **Animations** (`modules/appearance.lua`): three presets in a `presets` table (`snappy`: small overshoot; `smooth`: same speed, no bounce; `minimal`), chosen with `local preset = ...` and a reload; the drop-down/scratchpad slide is set separately after them. Current choice (Nov 2026, the user may experiment more): `minimal` (windows 0.15 s, mostly fades), but with workspaces sliding in 0.2 s. Speeds are tenths of a second. Lessons from tuning: an ease-in-out curve feels sluggish (slow start), so the presets use `easeOutQuint`/`overshoot`; the user prefers fast (0.15–0.25 s) and a light overshoot (~5%) over a strong one. **Wobble** (`decoration.wobble`, new in 0.57: windows deform while moved/resized) is on with `stiffness = 450`, `damping = 22` (defaults 200/12 felt sluggish), `intensity = 0.2`.
  - **Groups** (tabs, `SUPER + G`): `group` in `modules/appearance.lua` takes its colours from the theme palette like the window borders (border gradient accent→accent2, inactive dim, locked groups warn); the groupbar draws filled tabs (`gradients = true`, no indicator line), active = accent with bg text, others = surface with fg text, JetBrainsMono Nerd Font 15 in 24 px tabs (groupbar `font_size` is in pixels, unlike kitty/mako points: kitty 12 pt ≈ 16 px), 6px rounding.
  - **Dimming**: `decoration.dim_inactive` with `dim_strength = 0.2` (`modules/appearance.lua`; 0.12 was too faint); mpv is exempt (`no-dim-video` rule, `no_dim = true`). No toggle key: the user doesn't want one.

PAGE_FLIP_ASYNC` in the Hyprland log) and the fullscreen game froze on its last frame; don't re-suggest it on this laptop. The panel is a fixed 60 Hz, which sets the lag floor.   - A lone tiled or maximized window gets no border/rounding (`hl.window_rule`) and `gaps_in = 0` (`hl.workspace_rule`; `gaps_out` deliberately left alone), matching workspace selectors `w[tv1]` and `f[1]` (syntax from `/usr/share/hypr/hyprland.lua`, which has a commented "smart gaps" example).

Without an official palette, apply reads the scheme's kitty colours with `kitten themes --dump-theme` and derives 8 slots (`bg`, `fg`; `surface`/`dim` = bg→fg blends; `accent`/`accent2`/`warn`/`crit` = ANSI blue/green/yellow/red, normal or bright variant by higher contrast on bg; then, for derived palettes only, a **contrast safeguard**: any of those four under 3:1 against bg is mixed toward black (light themes) or white (dark) in 2% steps until it reaches 3:1, keeping the hue; per-theme `overrides` are applied after and never adjusted; apply prints which slots it adjusted), writes `generated/{palette.lua,waybar.css,mako.conf,fuzzel.ini,hyprlock.conf}`, patches the two calendar colours in Waybar's `config.jsonc`, saves the theme name back into `palette.lua`, runs `kitten themes --reload-in=all` (which owns the `BEGIN_KITTY_THEME` block in `kitty.conf` and writes `current-theme.conf`) and reloads Hyprland, mako and Waybar. `SUPER + CTRL + T` opens the fuzzel picker, `SUPER + CTRL + SHIFT + T` runs `apply --previous` (back to the theme before the last switch; each switch writes the theme it leaves to `~/.local/state/theme/previous`, untracked, so pressing it twice flips between the last two; the picker lists that theme first as `↶ Name`). The picker: each theme shows a palette swatch (SVG in `~/.cache/theme-swatches/`, untracked) built with the same `derive()` as apply itself, from one `unzip -c` pass over `~/.cache/kitty/kitty-themes.zip` (each file parsed separately: about half have no `## name:` line; names can have extra spaces). Themes missing background/foreground/red are left out, since apply can't use them. The picker uses tall lines (`--line-height 44`) and an opaque background so the swatches read well, and marks lines `✓ ` (current theme), `★ ` (favourite) or two spaces; `unmark()` strips the prefix from fuzzel's answer. Each line is `marker name<TAB>tags`, with tags `light`/`dark` (same bg-vs-fg rule as below), `favorite`, `previous`; fuzzel shows only column 1 (`--with-nth=1`), searches both (`--match-nth='{1} {2}'`) and returns column 1 (`--accept-nth=1`), so typing light, dark or fav filters. Qt apps (qt6ct) don't follow yet. Hyprland's `modules/appearance.lua` `dofile`s `generated/palette.lua`. Configs include their generated file (`@import`, `include=`, `source =`); never hand-edit `generated/`, and commit it with `palette.lua`. ## Validating changes

No build/test suite. To sanity-check:
- Lua syntax: `luac -p <file.lua>`
- Hyprland reload / errors: `hyprctl reload`, then `hyprctl configerrors`
- Keybindings: `~/.config/hypr/scripts/keybinds.sh --check` (after the reload) reports binds without a description or section and keys bound twice
- Waybar: `pkill waybar; uwsm app -- waybar &` (or `pkill -SIGUSR2 waybar` to reload)
- Mako: `makoctl reload`
- If `hyprctl` says "Couldn't connect to .../.socket.sock", the shell's `HYPRLAND_INSTANCE_SIGNATURE` is from an old session (e.g. after a re-login): `export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1)`
