# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`~/.dotfiles` is a **bare git repo** (remote `git@github.com:jensk2k/dotfiles.git`) whose work tree is `$HOME`. `~/.dotfiles` itself contains only git internals; the config files live at their real paths under `/home/jk`. Edit files in place (e.g. `~/.config/hypr/hyprland.lua`). This file (`~/CLAUDE.md`) is tracked in the repo too.

Machine: Arch Linux, Hyprland session launched through **uwsm**.

## Git commands

Always pass the git-dir and work-tree explicitly (the shell alias `dotfiles` does this, but aliases aren't available in non-interactive shells). Run from `$HOME`, not from inside `~/.dotfiles`, or git gets confused about the work tree:

```sh
cd ~ && git --git-dir=$HOME/.dotfiles --work-tree=$HOME status
git --git-dir=$HOME/.dotfiles ls-tree -r --name-only HEAD   # list tracked files
```

- `status.showUntrackedFiles = no`, and `core.excludesfile` (`~/.gitignore_global`) is `*` — everything is ignored by default. **New files must be added with `git add -f <path>`**. Modified tracked files can be added normally, but under an ignored directory like `.config` git still prints an "ignored by .gitignore" hint and exits non-zero even though the files were staged — don't chain `&& git commit` after it (or just use `-f`).
- In zsh, a `G="git --git-dir=..."` variable won't word-split; use a function (`G() { git --git-dir=$HOME/.dotfiles --work-tree=$HOME "$@"; }`).
- `lgdot` alias opens lazygit on this repo.
- Commit messages are short, lowercase, imperative ("update zsh config").

## Tracked configs and how they connect

- **Hyprland** (`~/.config/hypr/`) uses the **Lua config format** (`hyprland.lua`, `hl.*` API), not classic `hyprland.conf`. `hyprland.lua` only `require`s the modules in `modules/`, in order: `keybindings`, `autostart`, `monitors` (catch-all monitor + the generated files), `appearance` (general/decoration/animations/dwindle), `input` (keyboard, touchpad, gestures), `rules` (window and workspace rules). New settings go in the matching module. Dispatchers via `hyprctl dispatch` also take Lua expressions (`hl.dsp.window.close({...})`).
  - `monitors.{conf,lua}` and `workspaces.{conf,lua}` are generated by **nwg-displays** — don't hand-edit. `modules/monitors.lua` defines a catch-all `hl.monitor` and then `require`s the generated `monitors.lua`/`workspaces.lua` from the config root (the `.conf` versions are unused).
  - Autostarted apps are launched with `uwsm app -- <cmd>`; keep that wrapper for anything new. Session env vars (cursor, GTK/Qt theme) live in `~/.config/uwsm/env`, not in `hl.env` calls; changes need a re-login.
  - Companion daemons: hypridle (runs hyprlock), hyprpaper, hyprsunset.
  - A lone tiled or maximized window gets no border/rounding (`hl.window_rule`) and `gaps_in = 0` (`hl.workspace_rule`; `gaps_out` deliberately left alone), matching workspace selectors `w[tv1]` and `f[1]` (syntax from `/usr/share/hypr/hyprland.lua`, which has a commented "smart gaps" example).
- **Waybar ↔ Hyprland/Mako**: Waybar modules call `~/.config/hypr/scripts/toggle-popup.sh <app-id> <cmd>` (opens a TUI like `bluetui` in a floating kitty window via `kitty --class`, with `confirm_os_window_close=0` so a second toggle closes it without kitty's "Close OS window" prompt; the class must start with `popup.` to match the `bar-popups` window rule in `modules/rules.lua`). The power button uses Waybar's native GTK menu (`menu-file` → `~/.config/waybar/power-menu.xml`, ids mapped in `menu-actions`). The Mako DND keybind does `pkill -RTMIN+8 waybar` to refresh the `waybar/scripts/mako-dnd.sh` module — keep the signal number in sync if either side changes. Likewise `custom/idle` (signal 9) shows `~/.config/hypr/scripts/idle-inhibit.sh`, which toggles a transient user unit `idle-inhibit` running `systemd-inhibit --what=idle` (hypridle honours it); the Waybar click and `SUPER + CTRL + I` both use it.
- **Keybindings** (`modules/keybindings.lua`): modifier scheme `SUPER` = do/focus, `+ SHIFT` = move/send/stronger, `+ ALT` = resize/variant, `+ CTRL` = system (lock `L`, theme `T`, audio mixer `A`, Bluetooth `B`, power profile `P`, idle inhibit `I`, DND `N`). Directions take arrows and `h/j/k/l` (one loop). `SUPER + D` flips the dwindle split, `SUPER + Escape` opens the fuzzel `scripts/power-menu.sh`, `SUPER + CTRL + Tab` goes to the previous workspace. Keep new binds inside this scheme. Bind through the local `bind(keys, action, description, opts)` helper after a `group("Section")` call: every bind needs a description (stored as `Section|Description`), because `SUPER + ?` (`scripts/keybinds.sh`) builds the cheat sheet from `hyprctl -j binds` (Lua binds otherwise only show `__lua`), merging binds with the same section, description and modifiers. It toggles a near-fullscreen kitty window (class `keys.cheatsheet`, sized by the `cheatsheet` rule in `modules/rules.lua`, font 10, opaque) that lays sections out in columns with gawk and redraws on resize; `--print` gives plain text. Its legend line is parsed from the "Modifier scheme" header comment in `keybindings.lua` (the single place the rules are written), so change the scheme there.
- **Launcher / menus**: fuzzel — app launcher (`SUPER + Space`), clipboard picker (`cliphist` → `fuzzel --dmenu`). `~/.config/fuzzel/fuzzel.ini` uses `launch-prefix=uwsm app --`, `dpi-aware=no` (otherwise text renders ~1.6x larger than mako on this ~157 DPI panel) and colours from the theme (see below). fuzzel menus hold the keyboard exclusively. Tried and rejected: `keyboard-focus=on-demand` (focus-follows-mouse closes it), and click-to-toggle from a Waybar icon (Hyprland doesn't pass bar clicks through while fuzzel holds the keyboard).
- **Waybar workspaces**: `hyprland/workspaces` shows only occupied workspaces (plus the active one; no `persistent-workspaces`) as `{id} {windows}`, with one Nerd Font glyph per window from `window-rewrite` (title rules first, so yazi/nvim inside kitty get their own icon; `popup.*` and `keys.cheatsheet` map to nothing; `window-rewrite-default` for the rest). Add a `class<...>` rule when a new app shows the default icon (`hyprctl -j clients | jq -r '.[].class'` gives the class).
- **Wi-Fi**: nm-applet in the Waybar tray only; there is no Waybar `network` module or networkmanager_dmenu.
- **Theme** (`~/.config/theme/`): `palette.lua` names a **kitty theme** (any `kitten themes` name) plus `bg_alpha`, picker `favorites` and per-theme slot `overrides`. `./apply [NAME|--pick]` (Lua) reads that theme with `kitten themes --dump-theme`, derives 8 slots (`bg`, `fg`; `surface`/`dim` = bg→fg blends; `accent`/`accent2`/`warn`/`crit` = ANSI blue/green/yellow/red, normal or bright variant by higher contrast on bg), writes `generated/{palette.lua,waybar.css,mako.conf,fuzzel.ini,hyprlock.conf}`, patches the two calendar colours in Waybar's `config.jsonc`, saves the theme name back into `palette.lua`, runs `kitten themes --reload-in=all` (which owns the `BEGIN_KITTY_THEME` block in `kitty.conf` and writes `current-theme.conf`) and reloads Hyprland, mako and Waybar. `SUPER + CTRL + T` opens the fuzzel picker. Hyprland's `modules/appearance.lua` `dofile`s `generated/palette.lua`. Configs include their generated file (`@import`, `include=`, `source =`); never hand-edit `generated/`, and commit it with `palette.lua`. Not themed: the neutral white hover tints in `style.css`, hyprlock's transparent input fill, window shadows (plain black). Shared non-colour style: font JetBrainsMono Nerd Font; 6px corner radius.
- **Login screen (SDDM)**: source in `~/.config/sddm/`: `sddm.conf` (the whole config; no `/etc/sddm.conf.d` files) and `theme/`, a from-scratch Qt 6 QML theme (`Main.qml`; layout in `theme.conf`, colours in `theme.conf.user` which `~/.config/theme/apply` generates). SDDM can't read `$HOME`, so `sudo ~/.config/sddm/install` copies them to `/etc/sddm.conf` and `/usr/share/sddm/themes/dotfiles`, plus the hyprpaper wallpaper as `background`; `apply` prints a reminder when the installed colours are stale. Preview without logging out: `sddm-greeter-qt6 --test-mode --theme ~/.config/sddm/theme` (needs a local `theme/background` copy, which is untracked; power buttons may not show in test mode, since they depend on `sddm.canReboot`/`canPowerOff`). The theme always picks the uwsm Hyprland session. X11 greeter (default `DisplayServer`).
- **Terminal**: kitty (`$TERMINAL`, keybindings, popups); colours follow the desktop theme. foot is no longer tracked.

## Validating changes

No build/test suite. To sanity-check:
- Lua syntax: `luac -p <file.lua>`
- Hyprland reload / errors: `hyprctl reload`, then `hyprctl configerrors`
- Keybindings: `~/.config/hypr/scripts/keybinds.sh --check` (after the reload) reports binds without a description or section and keys bound twice
- Waybar: `pkill waybar; uwsm app -- waybar &` (or `pkill -SIGUSR2 waybar` to reload)
- Mako: `makoctl reload`
- If `hyprctl` says "Couldn't connect to .../.socket.sock", the shell's `HYPRLAND_INSTANCE_SIGNATURE` is from an old session (e.g. after a re-login): `export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1)`

## Roadmap

The user's goals for this setup, in no particular order. Notes are starting points, not decisions. Remove an item once it's done.

- **Tidy up `~/.config/`**: it has ~87 entries, many for apps that are no longer installed. Cross-check each against `pacman -Qo`/installed packages and confirm with the user before deleting anything (some are untracked app state).
- **Keyboard first, mouse supported**: the main Waybar actions now have `SUPER + CTRL` keys and there's a keyboard power menu; look for what's still mouse-only (e.g. tray/nm-applet Wi-Fi, mpris controls beyond media keys, workspace overview) and fit new keys into the modifier scheme.
- **Slowly morphing shader wallpaper**: one GLSL shader whose image is a pure function of wall-clock time, so every screen shows the same moment. Desktop: a small headless renderer (C, EGL surfaceless + GLES on the Intel UHD, writes a PNG) handed to hyprpaper, about once a minute, with the rate set by power profile (e.g. 30 s / 1 min / 5 min); changes between frames must be small enough not to pop, plus dithering against banding. Login: live 60 fps `ShaderEffect` in the SDDM theme (compile with `/usr/lib/qt6/bin/qsb`). Lock: hyprlock can't run shaders and nothing can draw over a session lock (don't write a custom locker), so render every few seconds via `reload_cmd`/`reload_time` and let `crossfade_time` smooth it. Colours: palette via `apply`, then time of day/year; weather (Open-Meteo, cached hourly, offline fallback, sends approximate location) last. Unverified: hyprpaper's IPC for swapping images (a bare `hyprctl hyprpaper` returned "Invalid request") and whether swaps flash. Plan: desktop prototype first (look + measured battery cost), then colours, login, lock, weather; ask the user what look they want (soft gradients are cheapest and hide steps best).
- **Smaller ideas**: more fuzzel menus (emoji picker, Bluetooth) and installing `mpv-mpris` so mpv shows up in the Waybar `mpris` module.
