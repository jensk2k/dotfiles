# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`~/.dotfiles` is a **bare git repo** (remote `git@github.com:jensk2k/dotfiles.git`) whose work tree is `$HOME`. `~/.dotfiles` itself contains only git internals; the config files live at their real paths under `/home/jk`. Edit files in place (e.g. `~/.config/hypr/hyprland.lua`). This file (`~/CLAUDE.md`) is tracked in the repo too.

Machine: Arch Linux, Hyprland session launched through **uwsm**.

## Git commands

Always pass the git-dir and work-tree explicitly (the shell alias `dotfiles` does this, but aliases aren't available in non-interactive shells). Run from `$HOME`, not from inside `~/.dotfiles`, or git gets confused about the work tree:

```sh
cd ~ && git --git-dir=$HOME/.dotfiles --work-tree=$HOME status
git --git-dir=$HOME/.dotfiles ls-tree -r --name-only HEAD   # list tracked files
```

- `status.showUntrackedFiles = no`, and `core.excludesfile` (`~/.gitignore_global`) is `*` — everything is ignored by default. **New files must be added with `git add -f <path>`**. Modified tracked files can be added normally, but under an ignored directory like `.config` git still prints an "ignored by .gitignore" hint and exits non-zero even though the files were staged — don't chain `&& git commit` after it (or just use `-f`).
- In zsh, a `G="git --git-dir=..."` variable won't word-split; use a function (`G() { git --git-dir=$HOME/.dotfiles --work-tree=$HOME "$@"; }`).
- `lgdot` alias opens lazygit on this repo.
- Commit messages are short, lowercase, imperative ("update zsh config").

## Tracked configs and how they connect

- **Hyprland** (`~/.config/hypr/`) uses the **Lua config format** (`hyprland.lua`, `hl.*` API), not classic `hyprland.conf`. `hyprland.lua` only `require`s the modules in `modules/`, in order: `keybindings`, `autostart`, `monitors` (catch-all monitor + the generated files), `appearance` (general/decoration/animations/dwindle), `input` (keyboard, touchpad, gestures), `rules` (window and workspace rules). New settings go in the matching module. Dispatchers via `hyprctl dispatch` also take Lua expressions (`hl.dsp.window.close({...})`).
  - `monitors.{conf,lua}` and `workspaces.{conf,lua}` are generated by **nwg-displays** — don't hand-edit. `modules/monitors.lua` defines a catch-all `hl.monitor` and then `require`s the generated `monitors.lua`/`workspaces.lua` from the config root (the `.conf` versions are unused).
  - Autostarted apps are launched with `uwsm app -- <cmd>`; keep that wrapper for anything new. Session env vars (cursor, GTK/Qt theme) live in `~/.config/uwsm/env`, not in `hl.env` calls; changes need a re-login.
  - Companion daemons: hypridle (runs hyprlock), hyprpaper, hyprsunset.
  - A lone tiled or maximized window gets no border/rounding (`hl.window_rule`) and `gaps_in = 0` (`hl.workspace_rule`; `gaps_out` deliberately left alone), matching workspace selectors `w[tv1]` and `f[1]` (syntax from `/usr/share/hypr/hyprland.lua`, which has a commented "smart gaps" example).
- **Waybar ↔ Hyprland/Mako**: Waybar modules call `~/.config/hypr/scripts/toggle-popup.sh <app-id> <cmd>` (opens a TUI like `bluetui` in a floating kitty window via `kitty --class`; the class must start with `popup.` to match the `bar-popups` window rule in `modules/rules.lua`). The power button uses Waybar's native GTK menu (`menu-file` → `~/.config/waybar/power-menu.xml`, ids mapped in `menu-actions`). The Mako DND keybind does `pkill -RTMIN+8 waybar` to refresh the `waybar/scripts/mako-dnd.sh` module — keep the signal number in sync if either side changes.
- **Launcher / menus**: fuzzel — app launcher (`SUPER + Space`), clipboard picker (`cliphist` → `fuzzel --dmenu`). `~/.config/fuzzel/fuzzel.ini` uses `launch-prefix=uwsm app --`, `dpi-aware=no` (otherwise text renders ~1.6x larger than mako on this ~157 DPI panel) and colours from the theme (see below). fuzzel menus hold the keyboard exclusively. Tried and rejected: `keyboard-focus=on-demand` (focus-follows-mouse closes it), and click-to-toggle from a Waybar icon (Hyprland doesn't pass bar clicks through while fuzzel holds the keyboard).
- **Wi-Fi**: nm-applet in the Waybar tray only; there is no Waybar `network` module or networkmanager_dmenu.
- **Theme** (`~/.config/theme/`): `palette.lua` names a **kitty theme** (any `kitten themes` name) plus `bg_alpha`, picker `favorites` and per-theme slot `overrides`. `./apply [NAME|--pick]` (Lua) reads that theme with `kitten themes --dump-theme`, derives 8 slots (`bg`, `fg`; `surface`/`dim` = bg→fg blends; `accent`/`accent2`/`warn`/`crit` = ANSI blue/green/yellow/red, normal or bright variant by higher contrast on bg), writes `generated/{palette.lua,waybar.css,mako.conf,fuzzel.ini,hyprlock.conf}`, patches the two calendar colours in Waybar's `config.jsonc`, saves the theme name back into `palette.lua`, runs `kitten themes --reload-in=all` (which owns the `BEGIN_KITTY_THEME` block in `kitty.conf` and writes `current-theme.conf`) and reloads Hyprland, mako and Waybar. `SUPER + SHIFT + T` opens the fuzzel picker. Hyprland's `modules/appearance.lua` `dofile`s `generated/palette.lua`. Configs include their generated file (`@import`, `include=`, `source =`); never hand-edit `generated/`, and commit it with `palette.lua`. Not themed: the neutral white hover tints in `style.css`, hyprlock's transparent input fill, window shadows (plain black). Shared non-colour style: font JetBrainsMono Nerd Font; 6px corner radius.
- **Login screen (SDDM)**: source in `~/.config/sddm/`: `sddm.conf` (the whole config; no `/etc/sddm.conf.d` files) and `theme/`, a from-scratch Qt 6 QML theme (`Main.qml`; layout in `theme.conf`, colours in `theme.conf.user` which `~/.config/theme/apply` generates). SDDM can't read `$HOME`, so `sudo ~/.config/sddm/install` copies them to `/etc/sddm.conf` and `/usr/share/sddm/themes/dotfiles`, plus the hyprpaper wallpaper as `background`; `apply` prints a reminder when the installed colours are stale. Preview without logging out: `sddm-greeter-qt6 --test-mode --theme ~/.config/sddm/theme` (needs a local `theme/background` copy, which is untracked; power buttons may not show in test mode, since they depend on `sddm.canReboot`/`canPowerOff`). The theme always picks the uwsm Hyprland session. X11 greeter (default `DisplayServer`).
- **Terminal**: kitty (`$TERMINAL`, keybindings, popups); colours follow the desktop theme. foot is no longer tracked.

## Validating changes

No build/test suite. To sanity-check:
- Lua syntax: `luac -p <file.lua>`
- Hyprland reload / errors: `hyprctl reload`, then `hyprctl configerrors`
- Waybar: `pkill waybar; uwsm app -- waybar &` (or `pkill -SIGUSR2 waybar` to reload)
- Mako: `makoctl reload`
- If `hyprctl` says "Couldn't connect to .../.socket.sock", the shell's `HYPRLAND_INSTANCE_SIGNATURE` is from an old session (e.g. after a re-login): `export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1)`

## Roadmap

The user's goals for this setup, in no particular order. Notes are starting points, not decisions. Remove an item once it's done.

- **Tidy up `~/.config/`**: it has ~87 entries, many for apps that are no longer installed. Cross-check each against `pacman -Qo`/installed packages and confirm with the user before deleting anything (some are untracked app state).
- **Better workspace display in the Waybar `hyprland/workspaces` module**: e.g. per-workspace app icons (`window-rewrite`), only showing occupied workspaces, clearer active/urgent styling.
- **Keyboard first, mouse supported**: add hotkeys for almost everything that's currently mouse-only (Waybar actions like Bluetooth, volume mixer, power menu, idle inhibitor, DND, power profile).
- **Revisit keybindings**: check the grouping is logical, consider vi-style `hjkl` navigation next to the arrows, and research what other Hyprland users commonly do before proposing a scheme.
- **Keybinding cheat sheet on `SUPER + ?`**: show the keymap in an overlay or fuzzel list, ideally generated from `keybindings.lua` (or `hyprctl binds`) so it can't drift out of date.
- **Smaller ideas**: more fuzzel menus (emoji picker, Bluetooth) and installing `mpv-mpris` so mpv shows up in the Waybar `mpris` module.
