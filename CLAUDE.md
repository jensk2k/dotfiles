# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Scope:** these instructions are for working on the dotfiles. Because this file sits in `~`, Claude Code also loads it in every project below the home folder (e.g. `~/Projects/*`); there, ignore it and follow that project's own `CLAUDE.md`.

## What this is

`~/.dotfiles` is a **bare git repo** (remote `git@github.com:jensk2k/dotfiles.git`) whose work tree is `$HOME`. `~/.dotfiles` itself contains only git internals; the config files live at their real paths under `/home/jk`. Edit files in place (e.g. `~/.config/hypr/hyprland.lua`). This file (`~/CLAUDE.md`) is tracked in the repo too.

Machine: Arch Linux, Hyprland session launched through **uwsm**.

## Git commands

Always pass the git-dir and work-tree explicitly (the shell alias `dotfiles` does this, but aliases aren't available in non-interactive shells). Run from `$HOME`, not from inside `~/.dotfiles`, or git gets confused about the work tree:

```sh
cd ~ && git --git-dir=$HOME/.dotfiles --work-tree=$HOME status
git --git-dir=$HOME/.dotfiles ls-tree -r --name-only HEAD   # list tracked files
```

- `status.showUntrackedFiles = no`, and `core.excludesfile` (`~/.gitignore_global`) is `*` — everything is ignored by default. **New files must be added with `git add -f <path>`**. Modified tracked files can be added normally, but under an ignored directory like `.config` git still prints an "ignored by .gitignore" hint and exits non-zero even though the files were staged — don't chain `&& git commit` after it (or just use `-f`).
- In zsh, a `G="git --git-dir=..."` variable won't word-split; use a function (`G() { git --git-dir=$HOME/.dotfiles --work-tree=$HOME "$@"; }`).
- `lgdot` alias opens lazygit on this repo.
- Commit messages are short, lowercase, imperative ("update zsh config").

## Tracked configs and how they connect

- **Hyprland** (`~/.config/hypr/`) uses the **Lua config format** (`hyprland.lua`, `hl.*` API), not classic `hyprland.conf`. `hyprland.lua` only `require`s the modules in `modules/`, in order: `keybindings`, `autostart`, `monitors` (catch-all monitor + the generated files), `appearance` (general/decoration/animations/dwindle), `input` (keyboard, touchpad, gestures), `rules` (window and workspace rules). New settings go in the matching module. Dispatchers via `hyprctl dispatch` also take Lua expressions (`hl.dsp.window.close({...})`).
  - `monitors.{conf,lua}` and `workspaces.{conf,lua}` are generated by **nwg-displays** — don't hand-edit. `modules/monitors.lua` defines a catch-all `hl.monitor` and then `require`s the generated `monitors.lua`/`workspaces.lua` from the config root (the `.conf` versions are unused).
  - Autostarted apps are launched with `uwsm app -- <cmd>`; keep that wrapper for anything new. Session env vars (cursor, Qt platform theme) live in `~/.config/uwsm/env`, not in `hl.env` calls; changes need a re-login. Don't set `GTK_THEME` there: it would pin GTK apps to one theme, and `apply` switches light/dark (see Theme).
  - Companion daemons: hypridle (runs hyprlock), hyprpaper, hyprsunset.
  - Window rule `match` patterns must match the **whole** value (`^popup\\..*`, not `^popup\\.`); a prefix-only pattern silently never matches. Waybar's `window-rewrite` regexes are searches, so they don't need this. Desktop files' `StartupWMClass` can differ from the live class (Bitwarden is `bitwarden`); check with `hyprctl -j clients`.
  - A lone tiled or maximized window gets no border/rounding (`hl.window_rule`) and `gaps_in = 0` (`hl.workspace_rule`; `gaps_out` deliberately left alone), matching workspace selectors `w[tv1]` and `f[1]` (syntax from `/usr/share/hypr/hyprland.lua`, which has a commented "smart gaps" example).
- **Waybar ↔ Hyprland/Mako**: Waybar modules call `~/.config/hypr/scripts/toggle-popup.sh <app-id> <cmd>` (opens a TUI like `bluetui` in a floating kitty window via `kitty --class`, with `confirm_os_window_close=0` so a second toggle closes it without kitty's "Close OS window" prompt; the class must start with `popup.` to match the `bar-popups` window rule in `modules/rules.lua`). The power button uses Waybar's native GTK menu (`menu-file` → `~/.config/waybar/power-menu.xml`, ids mapped in `menu-actions`). The Mako DND keybind does `pkill -RTMIN+8 waybar` to refresh the `waybar/scripts/mako-dnd.sh` module — keep the signal number in sync if either side changes. Likewise `custom/idle` (signal 9) shows `~/.config/hypr/scripts/idle-inhibit.sh`, which toggles a transient user unit `idle-inhibit` running `systemd-inhibit --what=idle` (hypridle honours it); the Waybar click and `SUPER + CTRL + I` both use it.
- **Keybindings** (`modules/keybindings.lua`): modifier scheme `SUPER` = do/focus, `+ SHIFT` = move/send/stronger, `+ ALT` = resize/variant, `+ CTRL` = system (lock `L`, theme `T`, audio mixer `A`, Bluetooth `B` = `scripts/bluetooth-menu.sh` (fuzzel: connect/disconnect paired devices, power, open bluetui) and `SHIFT + B` = bluetui popup, power profile `P`, idle inhibit `I`, DND `N`). Directions take arrows and `h/j/k/l` (one loop). `SUPER + D` flips the dwindle split, `SUPER + Escape` opens the fuzzel `scripts/power-menu.sh`, `SUPER + CTRL + Tab` goes to the previous workspace, `SUPER + /` opens `scripts/window-finder.sh` (fuzzel list of all windows, Enter focuses), `SUPER + .` opens `scripts/emoji.sh` (fuzzel emoji picker from the `unicode-emoji` package's `emoji-test.txt`; copies with `wl-copy`, also types with `wtype` if installed), `SUPER + CTRL + W` opens `nmtui connect` as a bar popup, `SUPER + I` runs `hyprpicker -a -n -f hex` (colour picker: copies the hex and notifies), `SUPER + M` / `SUPER + SHIFT + M` invoke the newest notification's default action / pick one with `makoctl menu`. `SUPER + SHIFT + direction` is a Lua function bind: swap if tiled, move 40 px if floating. Directional focus only reaches tiled windows, so `SUPER + ALT + T` (also a function bind) jumps between the floating and tiled windows with the `floating`/`tiled` focus selectors. **Submaps (modes)**: `SUPER + R` enters resize mode (`hl.define_submap("resize", fn)`, entered with `hl.dsp.submap("resize")`, left with `hl.dsp.submap("reset")` on Esc/Return/`SUPER + R`); inside it plain `h/j/k/l`/arrows resize by 40 px and `SHIFT` by 120 px. Waybar's `hyprland/submap` module shows an accent pill with the mode name while one is active. Binds inside a submap use the same `bind()` helper and appear in the cheat sheet under their own section. Keep new binds inside this scheme. Bind through the local `bind(keys, action, description, opts)` helper after a `group("Section")` call: every bind needs a description (stored as `Section|Description`), because `SUPER + ?` (`scripts/keybinds.sh`) builds the cheat sheet from `hyprctl -j binds` (Lua binds otherwise only show `__lua`), merging binds with the same section, description and modifiers. It toggles a near-fullscreen kitty window (class `keys.cheatsheet`, sized by the `cheatsheet` rule in `modules/rules.lua`, font 10, opaque) that lays sections out in columns with gawk and redraws on resize; `--print` gives plain text; `--free` lists unused letters, digits and punctuation per modifier combination, for picking new binds. Its legend line is parsed from the "Modifier scheme" header comment in `keybindings.lua` (the single place the rules are written), so change the scheme there.
- **Launcher / menus**: fuzzel — app launcher (`SUPER + Space`), clipboard picker (`cliphist` → `fuzzel --dmenu`). `~/.config/fuzzel/fuzzel.ini` uses `launch-prefix=uwsm app --`, `dpi-aware=no` (otherwise text renders ~1.6x larger than mako on this ~157 DPI panel) and colours from the theme (see below). fuzzel menus hold the keyboard exclusively. Tried and rejected: `keyboard-focus=on-demand` (focus-follows-mouse closes it), and click-to-toggle from a Waybar icon (Hyprland doesn't pass bar clicks through while fuzzel holds the keyboard).
- **Battery notifications**: `~/.config/systemd/user/battery-notify.timer` (enabled under `graphical-session.target`, so it runs only in the session) runs `~/.config/hypr/scripts/battery-notify.sh` every minute: a normal mako notification at 15% and a critical one (stays, shown through DND) at 5% while discharging, once each per discharge (state in `$XDG_RUNTIME_DIR/battery-notify.state`; plugging in resets it). Thresholds are at the top of the script; `BATTERY=/some/dir` points it at a fake battery for testing.
- **Automatic power profiles**: `power-profile-auto.service` (user unit, enabled under `graphical-session.target`) runs `~/.config/hypr/scripts/power-profile-auto.sh`, which follows `upower --monitor` and acts only when `/sys/class/power_supply/AC/online` changes: unplugging saves the current profile to `$XDG_RUNTIME_DIR/power-profile-auto.saved` and sets power-saver; plugging in restores it (default balanced). A profile set by hand in between is kept until the next plug/unplug; starting on battery counts as an unplug.
- **Waybar workspaces**: `hyprland/workspaces` shows only occupied workspaces (plus the active one; no `persistent-workspaces`) as `{id} {windows}`, with one Nerd Font glyph per window from `window-rewrite` (title rules first, so yazi/nvim inside kitty get their own icon; `popup.*` and `keys.cheatsheet` map to nothing; `window-rewrite-default` for the rest). Add a `class<...>` rule when a new app shows the default icon (`hyprctl -j clients | jq -r '.[].class'` gives the class).
- **Waybar privacy**: the `privacy` module (first in `modules-right`) shows a red pill only while the microphone (`audio-in`) or screen sharing is in use; Waybar can't watch the camera. Test with `timeout 5 pw-record /dev/null`.
- **Wi-Fi**: nm-applet in the Waybar tray, plus `SUPER + CTRL + W` (nmtui popup) for the keyboard; there is no Waybar `network` module or networkmanager_dmenu.
- **Theme** (`~/.config/theme/`): `palette.lua` names a **kitty theme** (any `kitten themes` name) plus `bg_alpha`, picker `favorites` and per-theme slot `overrides`. `./apply [NAME|--pick]` (Lua) reads that theme with `kitten themes --dump-theme`, derives 8 slots (`bg`, `fg`; `surface`/`dim` = bg→fg blends; `accent`/`accent2`/`warn`/`crit` = ANSI blue/green/yellow/red, normal or bright variant by higher contrast on bg), writes `generated/{palette.lua,waybar.css,mako.conf,fuzzel.ini,hyprlock.conf}`, patches the two calendar colours in Waybar's `config.jsonc`, saves the theme name back into `palette.lua`, runs `kitten themes --reload-in=all` (which owns the `BEGIN_KITTY_THEME` block in `kitty.conf` and writes `current-theme.conf`) and reloads Hyprland, mako and Waybar. `SUPER + CTRL + T` opens the fuzzel picker: each theme shows a palette swatch (SVG in `~/.cache/theme-swatches/`, untracked) built with the same `derive()` as apply itself, from one `unzip -c` pass over `~/.cache/kitty/kitty-themes.zip` (each file parsed separately: about half have no `## name:` line; names can have extra spaces). Themes missing background/foreground/red are left out, since apply can't use them. The picker uses tall lines (`--line-height 44`) and an opaque background so the swatches read well, and marks lines `✓ ` (current theme), `★ ` (favourite) or two spaces; `unmark()` strips the prefix from fuzzel's answer. Ctrl+S (fuzzel `custom-1`, exit code 10, bound in `~/.config/theme/fuzzel-picker.ini`, which includes the normal fuzzel config) toggles the highlighted theme as a favourite (rewrites the `favorites` block in `palette.lua`) and reopens the picker on it (`--select-index`); the placeholder says so. **Light/dark**: a theme is light when bg is lighter than fg; apply then sets `gsettings` `color-scheme` (prefer-light/dark, which xdg-desktop-portal-gtk passes to browsers and websites), `gtk-theme` (Adwaita/Adwaita-dark) and `icon-theme` (Papirus/Papirus-Dark), and the matching lines in `~/.config/gtk-{3,4}.0/settings.ini` (nwg-look's files, untracked). Qt apps (qt6ct) don't follow yet. Hyprland's `modules/appearance.lua` `dofile`s `generated/palette.lua`. Configs include their generated file (`@import`, `include=`, `source =`); never hand-edit `generated/`, and commit it with `palette.lua`. Waybar sets `color: @fg` on `#waybar` (modules override it) and its hover/separator tints are `alpha(@fg, …)`, so the bar works on light themes; without the explicit colour, text falls back to the GTK theme and goes light-on-light. Not themed: window shadows (plain black). Shared non-colour style: font JetBrainsMono Nerd Font; 6px corner radius.
- **Login screen (SDDM)**: source in `~/.config/sddm/`: `sddm.conf` (the whole config; no `/etc/sddm.conf.d` files) and `theme/`, a from-scratch Qt 6 QML theme (`Main.qml`; layout in `theme.conf`, colours in `theme.conf.user` which `~/.config/theme/apply` generates). SDDM can't read `$HOME`, so `sudo ~/.config/sddm/install` copies them to `/etc/sddm.conf` and `/usr/share/sddm/themes/dotfiles`, plus the hyprpaper wallpaper as `background`; `apply` prints a reminder when the installed colours are stale. Preview without logging out: `sddm-greeter-qt6 --test-mode --theme ~/.config/sddm/theme` (needs a local `theme/background` copy, which is untracked; power buttons may not show in test mode, since they depend on `sddm.canReboot`/`canPowerOff`). The theme always picks the uwsm Hyprland session. X11 greeter (default `DisplayServer`).
- **Terminal**: kitty (`$TERMINAL`, keybindings, popups); colours follow the desktop theme. foot is no longer tracked.

## Validating changes

No build/test suite. To sanity-check:
- Lua syntax: `luac -p <file.lua>`
- Hyprland reload / errors: `hyprctl reload`, then `hyprctl configerrors`
- Keybindings: `~/.config/hypr/scripts/keybinds.sh --check` (after the reload) reports binds without a description or section and keys bound twice
- Waybar: `pkill waybar; uwsm app -- waybar &` (or `pkill -SIGUSR2 waybar` to reload)
- Mako: `makoctl reload`
- If `hyprctl` says "Couldn't connect to .../.socket.sock", the shell's `HYPRLAND_INSTANCE_SIGNATURE` is from an old session (e.g. after a re-login): `export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1)`
